# Issue tracker

The repository is `gertyhiler/gertyhiler.github.io`; GitHub Issues is the tracker. No GitHub Project is configured. When no issue is assigned, the current user request is the task contract. Do not create fake issue references or copy Logistics organization/repository/Project IDs.

Use GitHub Issues directly via `gh` or an available connector. Search before creating; record objective, scope, acceptance and verification. Use one Issue for small work and the planning skills only when useful. GitHub Project columns represent delivery stage; triage labels represent current need. Keep supporting drafts under ignored `.agents/work/`.

Commits, pushes, comments, issue closure and deployment follow the user's authorization. Installation of a skill does not authorize external writes. No alternate task database, sync daemon or time tracker is required.
